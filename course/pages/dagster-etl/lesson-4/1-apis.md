# API

Построение ETL-пайплайнов для API во многом зависит от конкретного API, поскольку разные API по-разному организуют доступ к данным и их передачу. Каждый API имеет собственную структуру, конечные точки, требования к аутентификации и параметры запросов, которые могут значительно различаться.

Простые API часто возвращают данные в формате JSON в ответ на GET-запрос. При работе с большими наборами данных ответы обычно разбиваются на страницы, то есть для получения всех результатов необходимо выполнить несколько запросов.

Для API, управляющих масштабной или асинхронной обработкой данных, немедленный ответ с данными может быть невозможен. Вместо этого можно инициировать запрос, запускающий экспорт данных, после которого готовые данные попадут в отдельное хранилище (например, S3). Такие API требуют периодического опроса или логики обратного вызова для отслеживания готовности данных.

Поскольку универсального стандарта возврата данных API не существует, первым шагом при построении ETL-пайплайна для любого API должно быть внимательное изучение его структуры и поведения.

## API NASA

В этом уроке мы воспользуемся одним из общедоступных API NASA — NeoWs (Near Earth Object Web Service), предоставляющим сведения об астероидах. Это относительно простой API, возвращающий данные в JSON и не требующий пагинации или асинхронной обработки, поэтому он хорошо подходит для обучения. На его примере мы построим ETL-пайплайн из внешнего API в наше хранилище DuckDB.

**Примечание:** для этого API требуется ключ доступа, но получить его можно быстро и бесплатно. Для начала заполни [короткую форму](https://api.nasa.gov/) на портале NASA API. После отправки ты получишь ключ API, который мы будем использовать далее для аутентификации запросов.
