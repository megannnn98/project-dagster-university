# Приведение кода в порядок

Применим скилл **dignified-python** к коду, написанному в ходе курса. Промпты для него могут быть общими или очень конкретными. Начнём с общего вопроса, чтобы агент проверил кодовую базу на соответствие правилам dignified-python.

## Попроси скилл провести ревью

Укажи агенту проект (например, исходные ассеты и ресурсы) и попроси:

```text
/dignified-python Review the asset files in defs/assets/ and the resource definitions in defs/resources.py. Does this follow Python best practices?
```

Агент загружает контекст dignified-python и анализирует код. Он может сообщить о нескольких проблемах и предложить конкретные изменения.

## Примеры обнаруженных улучшений

Два типичных улучшения, которые может предложить скилл:

**1. Перенос `mkdir()` внутрь `resources()`**

В файле `resources.py` родительский каталог пути к базе данных может создаваться при импорте (например, вызовом `_DB_PATH.parent.mkdir(parents=True, exist_ok=True)` на уровне модуля). Это означает, что каталог создаётся сразу при импорте модуля. Такое поведение может быть неожиданным и затруднять тестирование или загрузку модуля в контекстах, где побочные эффекты пока нежелательны.

Скилл предлагает перенести вызов `mkdir()` внутрь функции построения `Definitions` (например, внутрь `resources()`), чтобы каталог создавался только при её вызове, то есть когда определения действительно загружаются, а не при каждом импорте.

**2. Замена повторяющейся логики ассетов вспомогательной функцией**

Три исходных ассета (`raw_customers`, `raw_orders`, `raw_payments`) могут быть определены тремя почти идентичными функциями, различающимися только URL, именем таблицы и именем ассета. Такое повторение нарушает принцип «не повторяйся», увеличивает размер файла и затрудняет изменения.

Скилл предлагает ввести одну вспомогательную функцию (например, `_make_raw_asset()`), принимающую URL, имя таблицы и имя ассета и возвращающую ассет. Три ассета по-прежнему зарегистрированы под прежними именами и в прежней группе, но определены через общую функцию без дублирования логики.

## Результат

После применения предложенных изменений код становится чище: нет побочных эффектов при импорте, меньше повторений. Можно выполнить `dg check defs`, чтобы убедиться, что определения по-прежнему загружаются, а для подтверждения неизменности поведения пайплайна следует выполнить тесты. Скилл dignified-python особенно полезен, когда нужно поручить агенту улучшение стиля и структуры без изменения поведения кода.
